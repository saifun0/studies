## Цель работы

Реализовать собственный шаблонный динамический массив `Vector<T>` с управлением памятью в куче (`new[]` и `delete[]`), автоматическим расширением при заполнении и базовыми операциями работы с элементами, а также разобраться с понятием амортизированной сложности и правилами управления ресурсами в C++.

---

## Теоретическая часть

Динамический массив хранит элементы подряд в непрерывном участке динамической памяти (куче), но в отличие от обычного статического массива умеет менять свой размер во время работы программы.

Внутри класса `Vector<T>` хранятся три приватных поля: указатель `T* data` на выделенный буфер, текущий размер `sz` (сколько элементов реально лежит в векторе) и емкость `cap` (на сколько элементов сейчас выделена память). Когда при вызове `push_back` размер достигает емкости (`sz >= cap`), выделяется новый массив вдвое большего размера, старые элементы копируются в него, а старый буфер освобождается через `delete[]`.

За счет стратегии удвоения емкости редкие переаллокации стоят `O(n)`, но суммарно на `n` вставок выполняется около `2n` копирований. В пересчете на одну операцию вставка в конец имеет амортизированную сложность `O(1)`.

## Листинг программы

```cpp
#include <iostream>
#include <windows.h>
#include <string>
#include <stdexcept>

using namespace std;

// Шаблонный класс динамического массива (аналог std::vector)
template <typename T>
class Vector {
private:
    T* data;  // указатель на массив в динамической памяти
    int sz;   // текущее количество элементов
    int cap;  // выделенная емкость

public:
    // Конструктор по умолчанию: пустой вектор, сложность O(1)
    Vector() : data(nullptr), sz(0), cap(0) {}

    // Конструктор с параметром размера, сложность O(n)
    explicit Vector(int n) : data(nullptr), sz(0), cap(0) {
        if (n > 0) {
            sz = n;
            cap = n;
            data = new T[cap];
            for (int i = 0; i < sz; i++) {
                data[i] = T();
            }
        }
    }

    // Деструктор освобождает выделенную память, сложность O(1)
    ~Vector() {
        delete[] data;
    }

    // Добавление в конец с удвоением емкости, сложность O(1) амортизированно
    void push_back(const T& value) {
        if (sz >= cap) {
            int newCap = (cap == 0) ? 1 : cap * 2;
            T* newData = new T[newCap];
            for (int i = 0; i < sz; i++) {
                newData[i] = data[i];
            }
            delete[] data;
            data = newData;
            cap = newCap;
        }
        data[sz] = value;
        sz++;
    }

    // Удаление последнего элемента, сложность O(1)
    void pop_back() {
        if (sz == 0) {
            cout << "Вектор пуст, удалять нечего!" << endl;
            return;
        }
        sz--;
    }

    // Текущий размер и емкость, сложность O(1)
    int size() const { return sz; }
    int capacity() const { return cap; }

    // Доступ по индексу с проверкой границ, сложность O(1)
    T& operator[](int index) {
        if (index < 0 || index >= sz) {
            throw out_of_range("Индекс выходит за границы вектора");
        }
        return data[index];
    }

    const T& operator[](int index) const {
        if (index < 0 || index >= sz) {
            throw out_of_range("Индекс выходит за границы вектора");
        }
        return data[index];
    }

    // Вывод элементов вектора, сложность O(n)
    void print() const {
        cout << "[";
        for (int i = 0; i < sz; i++) {
            cout << data[i];
            if (i < sz - 1) cout << ", ";
        }
        cout << "]" << endl;
    }
};

int main() {
    SetConsoleOutputCP(CP_UTF8); // включаем UTF-8 в консоли Windows

    // 1. Вектор через конструктор по умолчанию
    Vector<int> v;
    cout << "Начальный размер: " << v.size() << ", емкость: " << v.capacity() << endl;

    for (int i = 1; i <= 6; i++) {
        v.push_back(i * 10);
        cout << "push_back(" << i * 10 << ") -> размер: " << v.size()
             << ", емкость: " << v.capacity() << endl;
    }

    cout << "Элементы v: ";
    v.print();

    // Удаление элементов с конца
    v.pop_back();
    v.pop_back();
    cout << "После двух pop_back: ";
    v.print();
    cout << "Размер: " << v.size() << ", емкость: " << v.capacity() << endl;

    // 2. Вектор через конструктор с размером
    Vector<int> v2(4);
    for (int i = 0; i < v2.size(); i++) {
        v2[i] = i + 1;
    }
    cout << "\nВектор v2(4): ";
    v2.print();

    // 3. Проверка шаблонности на строках
    Vector<string> words;
    words.push_back("первый");
    words.push_back("второй");
    words.push_back("третий");
    cout << "\nВектор строк: ";
    words.print();

    // Проверка pop_back на пустом векторе
    Vector<int> emptyVec;
    emptyVec.pop_back();

    return 0;
}
```

## Анализ сложности операций

| Операция | Временная сложность | Пояснение |
| :--- | :--- | :--- |
| `Vector()` | `O(1)` | Обнуление указателя и счетчиков |
| `Vector(int n)` | `O(n)` | Выделение буфера на `n` элементов и заполнение значениями по умолчанию |
| `~Vector()` | `O(1)` (или `O(n)` для типов с деструктором) | Освобождение массива `delete[] data` |
| `push_back(value)` | `O(1)` амортизированно (`O(n)` в худшем) | При наличии свободного места одна запись; при переполнении удвоение буфера и копирование `sz` элементов |
| `pop_back()` | `O(1)` | Уменьшение счетчика `sz` на единицу |
| `size()` / `capacity()` | `O(1)` | Возврат значения поля |
| `operator[](index)` | `O(1)` | Прямое обращение по смещению в непрерывном массиве |
| `print()` | `O(n)` | Один проход по всем `sz` элементам |

## Ответы на контрольные вопросы

### 1. Почему динамический массив называется "динамическим"?
Потому что память под него выделяется не на этапе компиляции в стеке, а во время выполнения программы в куче (heap), и при нехватке места размер выделенного буфера можно увеличить.

### 2. Что такое ёмкость (capacity) и чем она отличается от размера (size)?
Размер (`size`) показывает, сколько элементов сейчас реально хранится в векторе. Емкость (`capacity`) показывает, под сколько элементов выделена память в буфере. Всегда выполняется `size <= capacity`.

### 3. Почему при расширении массива ёмкость удваивается, а не увеличивается на фиксированное число?
Если каждый раз добавлять фиксированное число (например, +1 или +10), при добавлении `n` элементов переаллокация и полное копирование будут происходить слишком часто, и общая стоимость `n` вставок вырастет до `O(n^2)`. При удвоении переаллокации случаются все реже (через 1, 2, 4, 8, ... элементов), что сохраняет линейное суммарное время `O(n)`.

### 4. Какова амортизированная сложность операции push_back? Почему?
Амортизированная сложность равна `O(1)`. При `n` последовательных вставках сумма всех копирований во время удвоений образует геометрическую прогрессию `1 + 2 + 4 + ... + n/2 < n`. Вместе с `n` обычными вставками выходит меньше `2n` операций на `n` вызовов, то есть в среднем меньше 2 операций на один `push_back`.

### 5. Что такое "правило трёх"? Когда оно применяется?
Правило трех гласит: если класс вручную управляет ресурсом (например, выделяет память через `new[]`) и ему потребовался собственный деструктор, конструктор копирования или оператор копирующего присваивания, то почти наверняка нужно явно реализовать все три этих метода. Иначе компилятор сгенерирует поверхностное копирование указателя, что приведет к двойному `delete[]` и утечкам.

### 6. Что такое "правило пяти"? Чем оно отличается от "правила трёх"?
Правило пяти (появилось в C++11) расширяет правило трех двумя методами для перемещения: конструктором перемещения `Vector(Vector&& other)` и оператором перемещающего присваивания `Vector& operator=(Vector&& other)`. Оно позволяет забирать указатель у временных объектов за `O(1)` вместо дорогого глубокого копирования.

### 7. В чём разница между конструктором копирования и оператором присваивания?
Конструктор копирования создает новый объект из существующего (например, `Vector<int> b = a;` или `Vector<int> b(a);`), когда у `b` еще нет собственной памяти. Оператор присваивания (`b = a;`) работает с уже существующим объектом `b`, поэтому перед копированием данных из `a` нужно корректно освободить старую память `b`.

### 8. Зачем нужна проверка `if (this != &other)` в операторе присваивания?
Она защищает от самоприсваивания вида `v = v;`. Без этой проверки оператор сначала освободил бы `data` через `delete[]`, а затем попытался бы скопировать элементы из уже освобожденной памяти.

### 9. Что такое итератор? Как он связан с указателем?
Итератор - это объект, который указывает на элемент контейнера и дает единый интерфейс обхода (`++`, `*`, `!=`). Для непрерывного массива вроде `Vector<T>` самым простым итератором может служить обычный указатель `T*`, так как арифметика указателей (`ptr++`) перемещает его точно к следующему элементу.

### 10. Зачем нужны методы `begin()` и `end()`?
`begin()` возвращает итератор на первый элемент контейнера (`data`), а `end()` возвращает итератор на позицию сразу за последним элементом (`data + sz`). Эта пара задает полуинтервал `[begin, end)`, с которым работают алгоритмы STL (`std::sort`, `std::find`) и циклы.

### 11. Как реализовать range-based for для своего контейнера?
Достаточно добавить в класс методы `begin()` и `end()` (обычные и `const`-версии), возвращающие итераторы, поддерживающие `++`, разыменование `*` и сравнение `!=`. Для `Vector<T>` хватит `T* begin() { return data; }` и `T* end() { return data + sz; }`.

### 12. Что такое "глубокое копирование"? Чем оно отличается от "поверхностного"?
При поверхностном копировании копируется только сам адрес указателя `data`, и два объекта начинают указывать на один и тот же массив в памяти (что ломает программу при вызове деструкторов). При глубоком копировании выделяется отдельный новый массив `new T[cap]` и в него поэлементно копируются данные, поэтому объекты становятся полностью независимыми.

### 13. Что такое семантика перемещения и зачем она нужна?
Семантика перемещения позволяет передавать владение ресурсом (указателем `data`) из временного (rvalue) объекта в новый объект без выделения новой памяти и копирования элементов. У исходного объекта при этом `data` обнуляется (`nullptr`), чтобы его деструктор не удалил переданный массив.

### 14. Почему конструктор перемещения помечается `noexcept`?
Пометка `noexcept` гарантирует компилятору, что перемещение не выбросит исключений. Контейнеры STL (включая `std::vector`) при переаллокации используют конструктор перемещения элементов только если он помечен `noexcept`, иначе ради безопасности исключений они вынуждены делать более медленное копирование.

### 15. Как правильно освобождать память в деструкторе?
Если память выделялась под массив через `new T[cap]`, освобождать ее нужно парным оператором `delete[] data;` (обязательно с квадратными скобками). Для `nullptr` вызов `delete[]` в C++ полностью безопасен и ничего не делает.
