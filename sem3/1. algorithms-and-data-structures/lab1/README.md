## Теоретическая часть

В объектно-ориентированном программировании классы взаимодействуют между собой через три основных вида связей:

| Отношение | Смысл связи | Время жизни части | Реализация в C++ |
| :--- | :--- | :--- | :--- |
| Ассоциация | "использует", "знает о" | Независимое | Указатели, ссылки |
| Агрегация | "состоит из" (слабое владение) | Независимое, часть переживает целое | Сырые указатели (`T*`), ссылки |
| Композиция | "состоит из" (полное владение) | Совпадает со временем жизни целого | Поля-объекты, `std::unique_ptr<T>` |

При композиции класс-целое сам создает свои части и отвечает за их уничтожение. Если использовать `std::unique_ptr<T>`, память освобождается автоматически при разрушении владельца, что исключает утечки памяти.

При агрегации части создаются отдельно и передаются в целое по указателю. Класс-целое только хранит адреса этих объектов, поэтому его деструктор не удаляет сами части. Перед обращением к сырому указателю нужно проверять его на `nullptr`, иначе программа аварийно завершится.

Статическое поле (`static`) принадлежит всему классу целиком, а не конкретному объекту, и существует в одном экземпляре. Статический метод вызывается через имя класса (`Book::getBookCount()`) даже тогда, когда ни одного объекта еще не создано, и может работать только со статическими членами.

## Листинг программ

### Базовый уровень (`part1_basic.cpp`)

```cpp
#include <iostream>
#include <windows.h>
#include <string>
#include <vector>
#include <memory>

using namespace std;

// Класс "Часть": комната существует только внутри дома
class Room {
private:
    string name;  // название комнаты
    double area;  // площадь комнаты

public:
    Room(const string& n, double a) : name(n), area(a) {
        cout << "Комната " << name << " создана." << endl;
    }

    ~Room() {
        cout << "Комната " << name << " удалена." << endl;
    }

    void print() const {
        cout << "Комната " << name << ", площадь: " << area << endl;
    }
};

// Класс "Целое": дом владеет комнатами (композиция)
class House {
private:
    string address;
    vector<unique_ptr<Room>> rooms; // unique_ptr автоматически удалит комнаты вместе с домом

public:
    House(const string& n) : address(n) {
        cout << "Дом " << address << " создан." << endl;
    }

    ~House() {
        cout << "Дом " << address << " удален." << endl;
    }

    // Комната создается прямо внутри дома
    void addRoom(const string& roomName, double roomArea) {
        rooms.push_back(make_unique<Room>(roomName, roomArea));
    }

    void print() const {
        cout << "Дом " << address << ":" << endl;
        for (const auto& room : rooms) {
            if (room != nullptr) room->print();
        }
    }
};

int main() {
    SetConsoleOutputCP(CP_UTF8); // включаем UTF-8 в консоли Windows

    // Ограничиваем время жизни дома блоком, чтобы увидеть удаление комнат до конца main
    {
        House zeleniy("Зеленый");
        zeleniy.addRoom("Спальня", 15.1);
        zeleniy.addRoom("Гостиная", 10.1);
        zeleniy.addRoom("Кухня", 5.1);
        zeleniy.print();
    }
    cout << "--- После блока дом уже снесён ---" << endl;
    return 0;
}
```

### Средний уровень (`part2_medium.cpp`)

```cpp
#include <iostream>
#include <windows.h>
#include <string>
#include <vector>

using namespace std;

// Класс "Часть": книга существует независимо от библиотеки
class Book {
private:
    string title;
    string author;
    int year;
    static int bookCount; // общий счетчик всех созданных книг

public:
    Book(const string& t, const string& a, int y) : title(t), author(a), year(y) {
        bookCount++;
        cout << "Книга " << title << " была создана." << endl;
    }

    ~Book() {
        bookCount--;
        cout << "Книга " << title << " была удалена." << endl;
    }

    // Статический метод доступен без создания объекта Book
    static int getBookCount() {
        return bookCount;
    }

    string getTitle() const {
        return title;
    }

    void print() const {
        cout << "Книга " << title << ". " << author << ", " << year << " г." << endl;
    }
};

// Определение статического поля вне класса
int Book::bookCount = 0;

// Класс "Целое": библиотека хранит указатели на внешние книги (агрегация)
class Library {
private:
    string name;
    vector<Book*> books; // сырые указатели: библиотека не владеет книгами

public:
    Library(const string& n) : name(n) {
        cout << "Библиотека " << name << " создана." << endl;
    }

    // При закрытии библиотеки сами книги не удаляются
    ~Library() {
        cout << "Библиотека " << name << " закрыта." << endl;
    }

    void addBook(Book* book) {
        // Защита от пустого указателя
        if (book != nullptr) {
            books.push_back(book);
            cout << "Книга " << book->getTitle() << " добавлена." << endl;
        } else {
            cout << "Пустой адрес!" << endl;
        }
    }

    void print() const {
        cout << "Библиотека " << name << ": " << endl;
        for (const auto* book : books) {
            if (book != nullptr) {
                book->print();
            }
        }
    }
};

int main() {
    SetConsoleOutputCP(CP_UTF8); // включаем UTF-8 в консоли Windows
    
    cout << "Сейчас " << Book::getBookCount() << " книг." << endl;

    // Книги создаются независимо от библиотеки
    Book b1("Земля", "Автор А. А.", 1999);
    Book b2("Марс", "Иванов И. И.", 1999);
    cout << "Сейчас " << Book::getBookCount() << " книг." << endl;

    // Библиотека живет только внутри этого блока
    {
        Library lib("Городская");

        lib.addBook(&b1);
        lib.addBook(&b2);
        lib.addBook(nullptr); // проверка обработки nullptr
        lib.print();
    }

    // После закрытия библиотеки книги все еще существуют
    cout << "Сейчас " << Book::getBookCount() << " книг." << endl;
    b1.print();

    return 0;
}
```

## Ответы на контрольные вопросы

### 1. Что такое композиция? Приведите пример.
Композиция - это сильная связь "часть-целое", при которой части принадлежат целому и не могут существовать без него. Например, дом (`House`) и его комнаты (`Room`): при сносе дома комнаты уничтожаются вместе с ним.

### 2. Что такое агрегация? Чем она отличается от композиции?
Агрегация - это более слабая связь "часть-целое", при которой части создаются независимо от целого и могут его пережить или одновременно относиться к разным объектам. В отличие от композиции, при агрегации целое не создает и не уничтожает части. Пример: библиотека (`Library`) и книги (`Book`).

### 3. Как реализовать композицию в C++? Приведите пример кода.
В C++ композицию реализуют тремя способами: вложенными полями-объектами, контейнерами вроде `std::vector<Room>` или умными указателями `std::unique_ptr<Room>`. Последний вариант удобен тем, что объекты не переезжают при расширении вектора и автоматически удаляются без ручного `delete`:

```cpp
class House {
    vector<unique_ptr<Room>> rooms;
public:
    void addRoom(const string& name, double area) {
        rooms.push_back(make_unique<Room>(name, area));
    }
};
```

### 4. Как реализовать агрегацию в C++? Приведите пример кода.
Агрегацию реализуют через сырые указатели (`T*`) или ссылки, которыми класс-целое не владеет. В деструкторе целого эти объекты не удаляются:

```cpp
class Library {
    vector<Book*> books;
public:
    void addBook(Book* book) {
        if (book != nullptr) {
            books.push_back(book);
        }
    }
};
```

### 5. В чём разница между временем жизни частей при композиции и агрегации?
При композиции время жизни частей полностью совпадает со временем жизни целого: они создаются внутри него и исчезают, как только целое уничтожается. При агрегации части создаются снаружи и продолжают существовать после уничтожения целого.

### 6. Что такое статическое поле класса? Чем оно отличается от обычного поля?
Статическое поле (`static`) принадлежит самому классу, а не отдельному его экземпляру. Обычное поле (например, `title` у `Book`) создается отдельно в каждом объекте, а статическое поле (`bookCount`) одно общее на все объекты класса.

### 7. Как объявить и определить статическое поле? Где оно хранится?
Внутри класса поле объявляется с ключевым словом `static` (`static int bookCount;`), а определяется вне класса с указанием типа и имени класса (`int Book::bookCount = 0;`). В C++17 также допустимо объявление с `inline static` внутри класса. Хранится такое поле в области статической памяти программы на протяжении всего времени ее выполнения, а не внутри памяти конкретных объектов.

### 8. Что такое статический метод? Можно ли из него обратиться к нестатическим полям?
Статический метод - это функция класса, которую можно вызывать без создания объекта через оператор `::` (например, `Book::getBookCount()`). Обращаться к обычным (нестатическим) полям из него нельзя, потому что у статического метода нет указателя `this` на конкретный экземпляр класса.

### 9. Для чего используются статические счётчики объектов?
Они позволяют отслеживать, сколько экземпляров класса сейчас существует в программе (увеличение в конструкторе, уменьшение в деструкторе). Это удобно для отладки утечек памяти, контроля времени жизни объектов, генерации уникальных ID и сбора общей статистики по всем экземплярам.

### 10. Что такое паттерн "Одиночка" (Singleton)? Для чего он нужен?
Singleton - это порождающий паттерн, который гарантирует существование только одного экземпляра класса на всю программу и дает к нему общую точку доступа через статический метод (обычно `getInstance()`). Его применяют там, где дублирование объекта вредно или бессмысленно: менеджер конфигурации, логгер, общий пул подключений.

### 11. Как запретить создание копий объекта (конструктор копирования)?
В C++11 и новее для этого помечают конструктор копирования и оператор копирующего присваивания спецификатором `= delete`:

```cpp
MyClass(const MyClass&) = delete;
MyClass& operator=(const MyClass&) = delete;
```

### 12. В каком порядке вызываются конструкторы и деструкторы при композиции?
Если части объявлены обычными полями внутри целого, при создании сначала вызываются конструкторы полей-частей (в порядке их объявления в классе), а потом тело конструктора целого. Если части добавляются динамически через метод (как в `addRoom`), их конструкторы отрабатывают в момент добавления. При уничтожении сначала выполняется тело деструктора целого (`~House`), а затем вызываются деструкторы его полей-частей в обратном порядке (у `vector<unique_ptr<Room>>` удаляются элементы, что вызывает `~Room()` для каждой комнаты).

### 13. Можно ли изменить статическое поле из обычного метода?
Да. Обычные (нестатические) методы имеют доступ как к полям своего экземпляра, так и ко всем статическим полям класса. Например, в конструкторе `Book` мы изменяем `bookCount++`, а в деструкторе делаем `bookCount--`.

### 14. Почему статические поля нужно определять вне класса?
Объявление класса (`class Book { ... };`) лишь описывает структуру типа, но не выделяет память под статическую переменную. Если заголовочный файл с классом подключить в нескольких `.cpp` файлах, память под общее поле должна быть выделена ровно один раз (правило одного определения, ODR), поэтому определение выносят наружу (`int Book::bookCount = 0;`).

### 15. В каких случаях стоит использовать композицию, а в каких - агрегацию?
Композиция подходит, когда часть не имеет смысла отдельно от целого и должна уничтожаться вместе с ним (дом и комнаты, заказ и его позиции). Агрегацию выбирают, когда объекты самостоятельны, могут жить дольше контейнера или входить сразу в несколько структур (книги и библиотека, студенты и учебный курс).
